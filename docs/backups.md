# Encrypted database backups

The GitHub Actions workflow `encrypted-backup.yml` runs daily at 02:30 UTC and can be started manually. It creates a PostgreSQL custom-format dump, encrypts it with GPG AES256, validates the encrypted dump can be listed, and stores the encrypted artifact for 30 days. After upload, the authenticated status endpoint writes `BACKUP_SUCCEEDED`; the admin health screen shows the last recorded success and flags records older than 48 hours.

Before enabling the workflow, set GitHub repository secrets `BACKUP_DATABASE_URL` (read-only backup role with SELECT on every relevant table), `BACKUP_PASSPHRASE` (random high-entropy passphrase), and `BACKUP_STATUS_SECRET`. Set repository variables `BACKUP_STATUS_URL` to `https://<production-domain>/api/backup/status` and `BACKUP_ENABLED=true`. Set the same `BACKUP_STATUS_SECRET` in the production application. Without these values, the workflow is disabled and the admin screen must show no successful backup. Store the passphrase separately from GitHub so archived data can be recovered if the account is lost.

To restore, download an encrypted artifact to a trusted machine with PostgreSQL client tools and GPG, set `RESTORE_DATABASE_URL` to an isolated empty database and `BACKUP_PASSPHRASE`, then run `scripts/restore-encrypted-backup.sh <archive.dump.gpg>`. Verify counts for Student, Assessment, TaskSubmission, PracticeLog, ExamResult, StudyPlan, and StudentReport in that isolated database before any production cutover. Run a manual restore drill after setup and periodically thereafter. GitHub artifact retention is 30 days; configure an independent long-term backup destination for longer retention or disaster recovery across GitHub account loss. The admin timestamp records successful upload and archive list validation, not a verified full restore.
